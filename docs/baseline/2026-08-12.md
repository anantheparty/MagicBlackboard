### Resolved performance review item

Integration review found that `magic-plait` initially performed a full clone/equality comparison of
board children for every Plait document operation and emitted full previous/current documents.
Because Plait may emit `set_node` once per animation frame while dragging, this violated the
summary/delta-oriented hot-path direction in `docs/01_ARCHITECTURE.md`.

The worktree implementation was corrected before the final gate: document events now carry an
adapter-local revision, changed element IDs, theme, and cloned operation summaries, while a full
snapshot is cloned only through the explicit `getSnapshot()` query. A regression applies a
`set_node` operation to an element with an observable expensive property and confirms the document
event does not read/clone that property. The P1 review item is closed at implementation level; the
final workspace test/typecheck/build gate is still required.

### Resolved controlled-value data-loss review item

Integration review found that the product `onChange` persisted new Drawnix children but did not
update the `value` supplied by the parent. A later product-level context/tutorial rerender could
therefore pass the originally loaded children back through the controlled wrapper and overwrite
new in-memory drawing.

The app session now keeps a mutable reference to the latest board state on every Drawnix change,
without scheduling a hot-path React update; any later parent rerender supplies the current children.

### Resolved persisted tool-state validation review item

Integration review found that the first tool-state parser checked record shape but could still admit
an arbitrary string pointer or a freehand preset index outside the restored preset array. Corrupt
persisted input could therefore select an unsupported Drawnix mode or index and then be rewritten
by autosave instead of remaining recoverable.

The parser now uses explicit allowlists for the current pointer and the remembered shape, arrow,
and freehand pointers. Default/custom preset indexes must be non-negative integers within the actual
preset array. Malformed tool-state slots remain locked and are not overwritten. Four regressions
cover an unknown current pointer, an unknown remembered shape, an out-of-range default index, and an
out-of-range custom index.

A later focused
`PATH=/opt/homebrew/opt/node@20/bin:$PATH npx nx test magic-blackboard --run --skip-nx-cache`
passed 2 files/30 tests after the pointer/index hardening. A subsequent storage-boundary pass limits
custom presets to the three items supported by the current UI, enforces its 1–24 stroke-width range,
and projects away unknown fields. That expanded app run passed 2 files/33 tests in 1.14 s. The same
worktree retained the `magic-plait` 13-test edge/hot-path suite described above.

The feature registry was also tightened so a toggle or availability write that rejects transitions
the existing in-memory feature to observable `write-error`, unavailable, and disabled state without
replacing the recoverable persisted value. `magic-core` then passed 3 files/14 tests in 218 ms, and
Magic Console passed 1 file/6 tests in 835 ms while distinguishing storage failure from ordinary
milestone unavailability. These were intermediate results; the final committed-tree gate below is
the authoritative workspace evidence.
